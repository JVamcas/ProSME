## Palette audit

The authoritative source is page 11 of
`docs/source-material/SME Fund Brand Identity (1).pdf`.

| Check                                              | Result                                                    |
| -------------------------------------------------- | --------------------------------------------------------- |
| Cream `#F6F4E2`                                    | Matches `brand-cream`                                     |
| Yellow `#FFCA45`                                   | Matches `brand-yellow`; regression test rejects `#FFD400` |
| Blue `#6BAED6`                                     | Matches `brand-blue`                                      |
| Navy `#0A183B`                                     | Matches `brand-navy`                                      |
| Gold `#C9A24D`                                     | Matches `brand-gold`                                      |
| Green `#16A34A`                                    | Matches the PDF hex value                                 |
| Orange `#FF6F00`                                   | Matches `brand-orange` and is the primary colour          |
| SME Fund identity                                  | Shared platform logo and portal contract use SME Fund     |
| Legacy dark orange classes/values in active source | Zero matches                                              |

The PDF prints green as RGB `22 173 74` while also printing hex `#16A34A`,
whose green channel is `163`. The application follows the explicit hex value.

Orange icons are mandatory for standalone brand, navigation, feature and action
icons. Navy is the required contrast exception on orange surfaces. Green and
gold icon exceptions are limited to explicit success/warning semantics with a
text cue.

## Retained programme decisions

These items do not block P3.1 because they are configuration, but they block
publication of the production workflow and final G3 acceptance:

- exact production stages and allowed transitions;
- final role grants and delegated decision authority;
- scoring criteria, maximum scores and weights;
- document categories, formats and size limits;
- information-request and outcome templates;
- panel quorum or multi-approver rules;
- ERP provider, schema and delivery protocol.

P3.3 must create the TOR-aligned reference workflow as a draft before any
workflow instance is created. No unapproved item may be embedded as
irreversible code or published as production policy.

## Acceptance decision

P3.0 is complete. P3.1 may start only through an explicit implementation
instruction and must use these contracts as its entry criteria.
