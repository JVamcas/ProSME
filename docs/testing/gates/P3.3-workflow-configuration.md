## Implementation evidence — 14 September 2026

- `0011_phase3_workflow_configuration.sql` creates the definition, version,
  stage, task, transition, opportunity-assignment, and append-only audit model.
  `0012_editable_workflows_before_instances.sql` permits graph edits regardless
  of lifecycle status until a runtime instance pins the version. The instance
  detection hook is ready for the P3.4 `app_workflow_instances` table.
  `0013_task_owned_assignment.sql` removes stage-level assignment storage so
  role/user assignment belongs exclusively to task definitions.
  Triggers continue to enforce published-only assignment, immutable audit
  history, controlled actions, valid lifecycle transitions, and
  assignment-free retirement.
- `WorkflowTaskRegistry.ts` registers all ten P3.0 task types with typed
  configuration and result schemas plus renderer keys, executable server
  handlers, allowed actions, and required capabilities. Declarative conditions
  use their own bounded registry and cannot contain executable code.
- The reference configuration contains the six TOR-aligned stages and remains a
  mutable draft until an authorised user validates and publishes it.
- Workflow administration follows component → TanStack Query hook → client
  service → admin API route → server service → repository. Every read and
  command checks the matching `workflow.definition.*` capability server-side.
- The editor supports adding, editing, and removing ordered tasks with
  registry-validated type configuration. Assignment belongs only to a task and
  selects either a configured PostgreSQL role or an active named staff user;
  stages never assign work. Versions stay editable until an instance exists.
- The editor also exposes applicant-safe labels, validation findings, cloning,
  publication, retirement, and funding-opportunity assignment in one
  capability-gated workspace.
- The isolated PostgreSQL suite applied every migration to a fresh database and
  passed 6/6 persistence, round-trip, pre-instance editing, clone, assignment,
  immutable-audit, assignment-detaching retirement, draft-transition, and
  representative-volume index-plan checks. Assignment audit entries persist the
  original command result for correct idempotent replay after reassignment.
- The full Vitest run passed 206 tests with
  14 intentionally skipped integration tests. The previous synthetic Playwright
  fixture has been replaced with a real authenticated-route check for Workflow
  Definitions, Opportunity Assignment, and Workflow Editor at desktop, tablet,
  and mobile sizes. Manual target comparison remains programme-owner review
  evidence and will be completed by the programme owner.
- ESLint and TypeScript passed. Architecture, form architecture, and file-size
  gates passed for 393 source files and 452 handwritten files. The Next.js
  production build passed and emitted the workflow pages and all workflow APIs.

The post-implementation review findings covering task contracts, transition
actions, retirement assignments, assignment replay, and draft-origin database
lifecycle transitions were resolved and regression-tested on 14 September 2026.
