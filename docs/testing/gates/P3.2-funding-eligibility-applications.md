## Implementation findings

- `/portal/applications` provides the target status tabs, a desktop table,
  mobile cards, progress, actions, and cursor pagination.
- `/portal/applications/new` searches and pages open opportunities and displays
  amount, deadline, and status before creation.
- `/portal/applications/[id]/edit` saves business, project, and financial
  sections independently, autosaves after inactivity, reports offline and
  recoverable retry states, resumes saved values, and never submits.
- Application lifecycle values remain data states. No status-specific
  filenames, functions, classes, components, services, or repositories were
  introduced.
- The shared status badge uses the approved cream, green, yellow, navy, and
  orange brand contract without white-on-green/yellow or generic red tokens.
- The repeatable `0010_phase3_application_creation.sql` migration creates the
  application table, owner/opportunity uniqueness, owner cursor index, checks,
  and applicant capabilities.
- The former browser-local demonstration and premature documents, review, and
  submission flow were removed. The former confirmation URL redirects to the
  application list.
